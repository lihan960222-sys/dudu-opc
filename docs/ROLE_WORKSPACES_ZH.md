# 在 Windows 管理页设置角色目录

1. 打开管理首页，在员工档案中选择管家或员工，可修改名称、头像、职责和执行引擎。创建员工时，从模型列表选取当前账户可用的模型。老板也可以在飞书告诉管家缺什么人，回到后台打开待审的建员卡补全资料并确认。
2. 在工作目录栏粘贴已有文件夹的绝对路径，或从旁边的目录浏览器选取。远程打开后台时，这里选择的也是家里主机上的目录。每个角色各用一个目录，目录之间不能互相嵌套。
3. 在家中主机上用文件资源管理器打开选好的目录。可自行创建「资料」「产物」子目录，单项任务的材料也可以放在「任务/任务标识」里。
4. 用 UTF-8 编辑目录根部的 **AGENTS.md**，写清职责、验收条件和汇报要求。已有的普通 Markdown 可以直接使用，模型取自员工档案。需要在文件里指定模型时，在顶部按下面的格式填入模型 ID。后台会在下一轮重新读取。

文件格式示例，模型占位符须替换：

```markdown
---
default_model: MODEL_ID
---

按图纸逐项核对焊接尺寸。回报时写清图纸版本、实测值、单位和未确认的尺寸。
```

本地改名后，历史会话仍关联原角色 ID。飞书里的机器人名称由对应的飞书应用管理，改名时请一并核对。旧运行方式的会话沿用创建时的目录。启用员工项目运行后，换目录再续办，后台会在原工单下交接。

## 员工项目运行方式（分岗位试点）

开启项目运行的员工在档案填写的目录执行命令，读项目指令，修改和核对产物。不同任务在后台分别保存会话。直接回复大嘴的原消息可以续办同一工单。更换员工、目录或供应商时，后台按工单交接已有成果；新员工的文件和飞书权限按自己的档案生效。

Windows 启动器从服务数据目录的 `employee-project-runtime.json` 读取试点名单。例如，`{"employees":[4],"weekly_knowledge":false}` 选择编号 4 的员工。已登录的普通 Windows 账号可以从现有后台启动 Codex App Server。后台把员工档案中的项目目录、模型和权限交给引擎，核对引擎的回执。一个任务保存一个原生会话编号，再次办理时接续该编号。

员工的原生会话保存在后台专用目录。需要缩短 Windows 路径时，可在服务环境中指定 `SUPARAGENT_EMPLOYEE_RUNTIME_ROOT`，使用服务专用的本机绝对路径。已有员工沿用原绑定。如果 Codex 报会话库打不开，请检查该目录的写入权限和完整路径长度。

日常派工使用现有服务。验证 Windows 能否拦住越权的子进程，以及项目依赖是否能正常启动，另用合成项目、普通权限和不可见窗口站进行。正式岗位可以分别启用。清空试点名单并重启服务即可恢复旧运行方式。

在员工的飞书连接里分别设置可读联系人、文档权限，以及可以处理私聊内容的模型供应商。员工要发布知识综述时，会读取消息正文、整理主题和来源，再读回云文档核对。检查文件夹需要员工应用取得用户权限 `space:document:retrieve`。老板在飞书开放平台发布权限后，还需回工作台完成该员工的用户授权。
